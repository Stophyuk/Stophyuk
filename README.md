## 만든 것

### 뷰토리 — 웹 · 모바일 앱 · 브라우저 확장을 하나로

블로그·유튜브 창작자를 위한 AI 콘텐츠 서비스. 3인 스타트업에서 **제품 총괄**을 맡았습니다.

세 플랫폼을 각각 만든 게 아니라 **하나의 서비스가 세 곳에 붙어 있는 구조**입니다.
계정은 하나고, **모바일에서 쓴 글을 PC 확장이 이어받아 실제로 발행**합니다.
구독 결제 · 본인인증 · 크레딧 차감까지 실제로 돌았고, 마케팅도 직접 했습니다.

`Next.js 16` `React 19` `Expo / React Native` `Chrome MV3` `DynamoDB` `Claude API` `Gemini`

> 가장 어려웠던 건 기능이 아니라 **원가**였습니다.
> 캐시를 두 겹으로 깔아 외부 API 소모를 줄였고, 요금은 기능 단위가 아니라
> **AI가 실제로 돌아가는 순간에만 차감**되도록 다시 설계했습니다.

### 참여형 캠페인 플랫폼 *(외부 발주 · 납품 완료)*

서명 → 유료 신청 → 굿즈 배송 → 완주 인증 → 순위 → 펀딩까지 한 사이트에서.
운영 인력이 한두 명이라 **사람 손을 없애는 것**이 진짜 요구사항이었습니다.

결제 금액은 브라우저가 보낸 값을 믿지 않고 **주문번호로 서버에서 다시 조회해 대조**한 뒤 승인합니다.
완주 인증은 기록 파일을 직접 분석해 자동으로 걸러냅니다.

`Next.js` `Supabase` `토스페이먼츠(빌링키)` `Upstash Redis` `d3 + topojson`

### 지지자 모집 플랫폼 *(외부 발주 · 납품 완료)*

오프라인 조직이 사람 모으는 일을 **지도 위 게임**으로. 모은 수만큼 응원봉이 10단계로 자랍니다.
조작 시도를 **네 겹으로 막되, 방어가 죽어도 진짜 사용자는 통과**하도록 설계했습니다.

`Next.js` `Supabase` `D3 geo` `Cloudflare Turnstile` `Google Sheets 연동`

### likethis desk — 콘텐츠 발행 자동화 데스크톱 앱

메모 하나를 쓰면 플랫폼별 톤으로 바꿔주고, 네이버 블로그에는 이미지까지 포함해 실제로 발행합니다.
원래 영상 제작·다중 플랫폼·댓글 자동화까지 붙어 있었는데,
1인용 도구로 다시 만들면서 **48,480줄 → 21,914줄로 절반 넘게 지웠습니다.**

`Electron` `Playwright` `better-sqlite3` `Claude API`

> 늘리는 것보다 지우는 게 어려웠습니다.
> 안 쓰는 기능이 화면에 보이면 결국 손대게 되기 때문입니다.

## 일하는 방식

| | |
|---|---|
| **01 · 문제를 그린다** | 업무 흐름을 같이 그려 사람 손이 가장 많이 드는 지점을 찾습니다. **안 되는 것은 먼저 안 된다고 말합니다** |
| **02 · 규칙을 만든다** | 코드를 쓰기 전에 색·글자·간격을 변수로, 컴포넌트를 상태별 변형까지. 화면이 늘어나도 일관성이 기억에 의존하지 않게 |
| **03 · 직접 만든다** | 화면·서버·DB를 혼자. 결제나 인증처럼 되돌릴 수 없는 곳은 **클라이언트를 믿지 않고 서버에서 다시 확인** |
| **04 · 굴리고 덜어낸다** | 어디서 멈추는지 숫자로 보고, 안 쓰는 기능은 지웁니다 |

개발이 빠른 이유는 손이 빨라서가 아닙니다.
**2단계에서 규칙을 정해두면 3단계에서 헷갈리는 시간이 사라지기 때문**입니다.
